# Build Guide: Xbox UWP

This guide builds the x64 UWP package for Xbox Dev Mode. The port keeps its
host, compatibility code, manifest, and assets under `ports/uwp`. The main
source tree still owns the game loop, SDL D3D11 renderer, input, audio, and
content handling.

Rendering, controller input, WASAPI playback, LocalState content loading, and
save-file creation were reported working on Xbox by the original PR author. This integration still
requires a local build and testing on hardware.

## Requirements

Install Visual Studio 2022 with the C++ UWP tools and Windows SDK
`10.0.19041.0`, plus LLVM/Clang, Ninja, CMake 3.24 or newer, and vcpkg.

Set the vcpkg checkout before building:

```powershell
$env:VCPKG_ROOT = '<path-to-vcpkg>'
```

Use vcpkg commit `80f9bcfa455e875d9c1bf7a7c6692d7e1e481061`. The same
revision is pinned in the workflow and `ports/uwp/vcpkg.json`. It builds FFmpeg,
mbedTLS, and zlib for `x64-uwp-static-md`. The patched SDL3-UWP 3.4.14 source is
committed under `ports/uwp/third_party/SDL3`.

## Build

Run the build script from the repository root:

```powershell
.\scripts\build\build-uwp.ps1
```

`Release` is the default. To include symbols, use:

```powershell
.\scripts\build\build-uwp.ps1 -Configuration RelWithDebInfo
```

CMake configures the matching preset and restores the vcpkg dependencies. The
generated package is placed under:

```text
ports/uwp/build/<preset>/AppPackages/SF3UWP
```

The script uses the pinned vcpkg revision declared in the manifest.
No build has been validated for this integration yet.

## Xbox One D3D11 shader compatibility

The UWP port uses Direct3D 11 at feature level `10_1`. Its advanced pixel
shader (including indexed texture palettes) is compiled as `ps_4_0` during
the build. FXC from the Windows SDK must be installed. CMake searches the SDK
binary directories and PATH; `SF3_UWP_FXC` can specify an absolute `fxc.exe`
path if automatic discovery fails.

The `SF3UWPShaders` target generates
`generated/shaders/d3d11/SF3_D3D11_PixelShader_Advanced_SM4.h` inside the preset's
build directory before compiling SDL3. Both the HLSL entry point and its shared
include are dependencies. SDL3 embeds this generated bytecode instead of its
precompiled `ps_5_0` header for this UWP build. Desktop builds keep their existing
shader selection. No global SDL installation is modified.

Run the normal UWP build script or reconfigure the existing CMake preset before
building in Visual Studio so the new shader target is available. The build must
stop if FXC is missing or shader compilation fails; there is no SM5 fallback in
this UWP configuration. Shader compilation and Xbox runtime validation remain
local validation steps.

After testing, copy `LocalState/data/uwp_render_check.log` before restarting the
app. For `shader=3`, the expected entry is `profile=ps_4_0 hr=0x00000000` with
`feature_level=0xA100`. The diagnostic also records the canvas dimensions and
viewport to check whether the menu scale recovers after successful shader setup.

## Xbox One performance diagnostics

`uwp_render_check.log` version 4 uses the `UWP Diagnostic Writer` thread for
file writes and flushes. The main thread only queues bounded messages; it does
not wait for disk I/O or queue space. The 128-entry queue occupies 512 KiB.
Captured diagnostics are not also forwarded to the synchronous debugger output.
The worker flushes about once a second and drains the queue on orderly shutdown.
A forced termination can lose recent messages. The log is capped at 4 MiB.

`[UWP_LOG]` reports dropped messages, queue high-water mark, file-limit discards,
I/O errors and maximum worker flush time. Queue pressure drops diagnostic
messages only; it does not drop game frames, audio or resources.

`[UWP_PERF] window` summarizes 120 frames, including average/maximum times,
counts above 20/33.333 ms, texture creation counts/failures, and audio queue
snapshots. Up to eight slow-frame details per window identify the current
G/D state, frame phases, texture creation cost and screenshot cost. State changes
are also logged. These counters do not require the desktop debug CSV logger.
`legacy_debug_log=1` indicates that the separate desktop logger is also enabled;
its synchronous I/O can still affect performance.

`frame_ms` covers BeginFrame through EndFrame, including pacing. `work_ms`
excludes pacing; `pre_render_ms` includes BeginFrame and game_step_0, including
texture creation there. Texture creation time is a subset, not an additional
phase to add to the total. `previous_begin_interval_ms` measures the preceding
BeginFrame-to-BeginFrame interval, including game_step_1, event polling and
diagnostic enqueue overhead. It belongs to the preceding interval, whereas the
other detail fields describe the current frame. Use `avg_begin_interval_ms` and
`max_begin_interval_ms` to assess full loop cadence. Phase timers measure CPU
elapsed time, including driver waits; they are not GPU execution timestamps.
Audio byte counts are snapshots and do not prove absence of underruns.
`[UWP_PERF] afs_sync` records up to 64 synchronous reads exceeding 2 ms, with
resource/thread IDs and completion status. A limit marker indicates when later
slow reads stop being detailed. Reads retain their existing behavior.

Verbose viewport/geometry and successful-texture messages are disabled by
default. Set the SDL hint/environment `SF3_UWP_VERBOSE_RENDER_TRACE=1` only
when investigating rendering correctness. Render/shader errors remain logged.
Shader Model 4, existing caches, audio loading and frame pacing are unchanged.
The session header reports main/logger thread IDs and logical CPU count; this
does not enumerate all process threads or establish an exclusive CPU allocation.

Version 4 enables indexed texture reuse by default on UWP, independently of the
desktop debug logger. It uses the existing indexed upload path: INDEX4 pixels
are expanded to INDEX8, with an RGBA streaming fallback if a palettized texture
cannot be created. Palette/pixel unlocks retain compatible cached textures that
have not been used in the current frame, then update them on demand. Textures
already referenced by this frame's render tasks retain their original data until
cleanup; a new cache entry is created if needed. Actual resource releases still
invalidate the cache. Dimension/format changes force recreation.

The SDL hint `SF3_UWP_TEXTURE_REUSE` is read at renderer initialization and defaults
to `1`; setting it to `0` before initialization provides the previous creation
path for comparison. `[UWP_RENDER] texture_reuse enabled=1 snapshot_protection=1`
confirms the selected path. Shader Model 4, audio loading and pacing are unchanged.

`[UWP_PERF] cache kind=slow` accompanies detailed slow frames. `kind=window`
aggregates the same 120 frames as the preceding window record: counters/bytes
are summed, update times are per-frame maxima, and `largest_create` is the
largest created texture by area. `retained` counts entries preserved on unlock,
not a resident-texture count; `hits` counts existing cache entries encountered
before any update. Invalidation counts distinguish pixels, palettes and actual
releases. `snapshot_invalidations` counts entries invalidated to preserve queued
draws, while `resize_recreates` also includes incompatible format changes.
`upload_bytes` counts successful indexed/RGBA pixel uploads through the reuse
helpers, including initial uploads; it excludes palette data, driver staging,
alignment and default-path uploads. It does not measure GPU memory usage.
Pixel update timing includes conversion where needed and can overlap creation
timing for initial uploads. Stage/area IDs, player character IDs, background
world X and player X positions identify the context of slow records and state
transitions; window context is sampled at the end, not throughout the window.

For the next console test, keep verbose rendering and desktop CSV diagnostics
disabled. Navigate title/menu, enter character select, play at least two rounds,
and repeat a mode transition. Compare the Alex stage with the quieter forest
stage, testing left, center and right positions and repeated attacks. Check
sprite animation, transparency, palette changes and super effects for visual
regressions. Note whether pauses occur only on first use or also on repetition.
Wait five seconds after the last action, then download
`uwp_render_check.log` and `uwp_resource_check.log` before restarting the app.
The last partial 120-frame window may not have a summary, but slow details and
state transitions are queued immediately. Build and runtime testing are local.

## Packaging and signing

This branch does not change the desktop release workflow. The local build produces
an unsigned package. Sign it with a code-signing certificate whose subject is
`CN=3SXW` before deployment when required by the console. Keep private keys and
passwords outside the repository. Install the matching x64 VCLibs framework dependency.

## Game data and storage

Do not package `SF33RD.AFS`, disc images, ROMs, or saves. Transfer a legally
obtained `SF33RD.AFS` through Xbox Device Portal to:

```text
LocalState/resources/SF33RD.AFS
```

Configuration, saves, and logs are written under `LocalState/data`. Press View
and Menu together to save screenshots under `LocalState/prints`.
On first launch, the bundled bezels are copied to `LocalState/data/img`. Existing
files in that folder are left unchanged.
Runtime code remains in the installed package.

## Xbox deployment

Install the signed MSIX and its framework dependencies through Xbox Device
Portal. Import the included public certificate if the console does not already
trust it.

## GitHub Actions: UWP branch

Push commits to `UWP` to run only `Build (Xbox UWP)`. Desktop push workflows
remain restricted to `main`; their jobs also skip PRs originating from `UWP`.
Do not create release tags for experimental builds: release tags still trigger
the existing multi-platform release workflow.

The Windows runner builds only `SF3UWP`, restores cached vcpkg dependencies,
and cancels older runs on the same branch. The first dependency build can take
substantially longer than later cached runs.

Download `3SXW-Xbox-UWP-test` from the completed Actions run. Extract the artifact
ZIP and then its inner ZIP. The package includes the signed MSIX, x64 VCLibs,
public test certificate and installation instructions. Private keys are not uploaded.
Each run uses a new temporary test certificate and version 1.0.0.0; this is for
fresh test installations, not a stable update channel. Back up LocalState before
uninstalling an earlier test package. A persistent certificate and incrementing
versions will be needed for dependable updates preserving installed app data.

If compilation fails, inspect the failed step and `Xbox-UWP-diagnostics` artifact.
No local build is required for this workflow.
